Each skill is `.pipeline/skills/{name}/SKILL.md`. Listed on a workflow allowlist, not under `.cursor/`.

| Skill | Purpose |
|-------|---------|
| `orchestration` | Receptionist: detect source, intake, resolve, route, drive |
| `ask` | Read-only Q&A |
| `feature-development` | Parent feature ladder, classes, sign-offs |
| `product-planning` | PM loop |
| `architecture-design` | Architect loop |
| `architecture-visualization` | Optional Archify deliver |
| `spec-generation` | BA loop |
| `epic-breakdown` | Epic children to specs |
| `jira-intake` | Read-only Jira fetch |
| `github-intake` | Read-only GitHub Issues/PR fetch |
| `bug-fix` | Analyst then repair |
| `test-design` | Structured cases |
| `test-knowledge-bootstrap` | Curator parent procedure |
| `observability-telemetry` | Product event extraction |
| `secure-implementation` | Security preflight |
| `ui-enhancement` | Layout/art direction only |
| `testing-unit` / `testing-api` / `testing-ui-playwright` / `testing-e2e` | Tester layers |
| `local-deployment` | Local build/serve/health |
| `pipeline-retro` | Learnings after devops |

Testing and local-deployment skills are the ones a **project** may adapt for runners and paths. Planning skill bodies stay portable.
