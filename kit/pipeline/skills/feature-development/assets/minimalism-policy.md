# Code minimalism policy (configurable)

| Attribute | Value |
|-----------|--------|
| Type | Policy |
| Audience | Architect and Developer agents |
| Adapt | Edit the `new_dependencies` column only. Do not add extra classes. |

Owned by **feature-development**. Architect applies this while designing (A3)
and records the outcome in `features/{slug}/state/architect-agent.json`.
Developer applies this on every file it adds or edits. Hooks read the recorded
declaration, so the Architect writing it down is what unblocks the Developer.

Edit the `new_dependencies` column only. Do not invent extra classes.

## Decision ladder (in order, stop at the first that works)

Work down the rungs. Do not skip to a lower rung without having answered the
higher one.

1. **Does it need to exist?** If no requirement in the spec, `patch.md`, or
   `rca.md` asks for it, do not build it. Out-of-scope extras are reverted.
2. **Does the repo already do this?** Search for an existing component, route,
   hook, util, or pattern. Import it rather than re-writing it.
3. **Is it in the standard library?** Use it.
4. **Is there a native platform feature?** A browser control, a CSS property,
   or a runtime API beats a package. `<input type="date">` is not a date picker
   dependency.
5. **Is it already an installed dependency?** Check the manifest before adding
   a second library that does the same job.
6. **Can it be one line?** Prefer the small expression over the abstraction.
   Three similar lines beat a premature helper.
7. **Only then write the minimum that satisfies the requirement.** No
   speculative options, no config for a case nobody asked for.

Fixing a cause beats handling a symptom, and deleting beats adding. A
deliberate shortcut is allowed when it is written down in the HANDOFF.

## Dependency table

| Class / workflow | new_dependencies | What that means |
|------------------|------------------|-----------------|
| micro | forbidden | Reuse only. No install, no manifest edit. |
| minor | forbidden | Reuse only. No install, no manifest edit. |
| feature (and jira-story / jira-epic at feature class) | allowed when declared | Architect declares it first; then the install is allowed |
| jira-bug | forbidden | Fix the cause with what the repo already has |

Defaults: new dependencies are **off** for micro, minor, and bugs. On
feature-class work they are allowed only after the Architect has declared them
(below).

## Declaring a dependency (feature class)

Architect records both, in the same step:

- `features/{slug}/state/architect-agent.json` →
  `context.new_dependencies: [{ "name": "…", "why_nothing_existing_works": "…" }]`
- `features/{slug}/HANDOFF-architect.md` → `**new_dependencies:** {comma list}`
  (or `none`)

`name` must be the exact package name the installer will see (`axios`, not
`the HTTP client`). `why_nothing_existing_works` must name the rung it failed:
what in the repo, the standard library, the platform, or the installed
manifest was checked and why it did not serve.

Architect also records what was reused, so the Developer does not re-search:

- `context.reuse_candidates: [{ "path": "…", "note": "…" }]`

Undeclared installs are refused by `before-shell.py`, and undeclared
`package.json` / `requirements.txt` edits by `pre-write.py`. The refusal names
the package and the fix. Declaring it is the unblock — not an environment
variable.

`npm install` with no package argument is allowed: it restores what the manifest
already pins and adds nothing new.

## One-run override

Set `ALLOW_DEPENDENCY={name}` (comma-separated for several) and that package is
allowed for this run only. Do not edit this file for a one-off.

`PIPELINE_ALLOW_DEPS=1` stays as break-glass for a human who needs the gate out
of the way entirely. It leaves no record of why, so prefer the declaration.

## Anti-patterns

Installing a library the spec never asked for · adding a second package that
does an installed package's job · wrapping a one-line expression in a helper
used once · a `why_nothing_existing_works` that restates the feature instead of
naming the rung it failed · setting `PIPELINE_ALLOW_DEPS=1` instead of
declaring · building for a requirement nobody wrote down.
