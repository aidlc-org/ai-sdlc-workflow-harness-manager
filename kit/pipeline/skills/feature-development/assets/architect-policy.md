# Architect policy (configurable)

| Attribute | Value |
|-----------|--------|
| Type | Policy |
| Audience | Parent (copies values into `route.md`) |
| Adapt | Edit the table columns only. Do not add extra classes. |

Owned by **feature-development**. Parent applies this **after** requirements
exist (`prd.md` or `intake.md` / `epic-plan.md`) and after
`@signoff:requirements`. Then write or update `skip_architect` in
`features/{slug}/route.md`.

Edit the `run_architect` column only. Do not invent extra classes.

| Class / workflow | run_architect | What runs when true |
|------------------|---------------|---------------------|
| micro | false | Never |
| minor | false | Never |
| jira-bug | false | Never |
| feature (and jira-story / jira-epic at feature class) | true if any **run trigger** below matches | `architect-agent` then `@signoff:architect` |

Defaults: Architect is **off** for micro, minor, and bugs. On feature-class
work it runs only when the story is large enough (triggers below).

## Run triggers (any one → run)

Read the signed-off requirements artifact. Run Architect if **any** match:

- 2+ proposed children (PM child table, epic story table, or intake that splits)
- New route, page, or information architecture
- New persistence, API, MCP, or third-party SDK
- Authn/authz, money, inventory, PII, or secrets
- UI designer `context.recommend_after_signoff` is `architect-agent`
- User typed `RUN_ARCHITECT: true`

Skip Architect on feature class when **none** of those match (single simple
child, no new API/persistence/authz) and the user did not force it.

## One-run override

If the user types `RUN_ARCHITECT: true` or `RUN_ARCHITECT: false`, that wins
for this `route.md` only. Do not edit this file for a one-off.

## Parent mapping

- `run_architect: true` → `skip_architect: false` and keep `architect-agent` + `@signoff:architect`
- `run_architect: false` → `skip_architect: true` and drop both of those steps

BA and `@signoff:ba` still run when Architect is skipped.
